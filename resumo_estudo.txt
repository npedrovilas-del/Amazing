 2. FICHEIRO DE CONFIGURACAO (config.txt)
===========================================================

Formato: KEY=VALUE (uma por linha, linhas com # sao ignoradas)

Chaves obrigatorias:
  WIDTH        = inteiro > 0          (largura em celulas)
  HEIGHT       = inteiro > 0          (altura em celulas)
  ENTRY        = x,y                  (coordenadas da entrada)
  EXIT         = x,y                  (coordenadas da saida)
  OUTPUT_FILE  = string               (nome do ficheiro de saida)
  PERFECT      = True ou False        (True = unico caminho)

Chave opcional:
  SEED         = inteiro              (default = 42 se omitido)

Regras de validacao (config.py linhas 58-83):
  1. ENTRY != EXIT
  2. WIDTH > 0, HEIGHT > 0
  3. ENTRY e EXIT dentro dos limites do grid (0 <= x < WIDTH, 0 <= y < HEIGHT)
  4. ENTRY e EXIT na BORDA do labirinto (x=0, x=WIDTH-1, y=0 ou y=HEIGHT-1)
  5. PERFECT = "True" ou "False" (case-sensitive)
  6. SEED e' opcional; se faltar, usa 42

===========================================================
 3. CLASSE Cell (mazegen/cell.py)
===========================================================

Atributos:
  x, y          : coordenadas no grid
  visited       : bool - foi visitado durante geracao?
  wall_north    : bool - True = parede norte fechada
  wall_south    : bool - True = parede sul fechada
  wall_east     : bool - True = parede este fechada
  wall_west     : bool - True = parede oeste fechada

Todas as paredes comecam fechadas (True) e visited = False.

===========================================================
 4. CLASSE MazeGenerator (mazegen/generator.py)
===========================================================

4.1 __init__(width, height, seed)
  - Faz seed do random (reprodutibilidade)
  - Cria grid bidimensional (lista de listas) de celulas Cell
  - Inicializa pattern_42 = [] (lista vazia)

4.2 get_neighbors(cell) -> list[Cell]
  - Devolve as 4 celulas ortogonalmente adjacentes (cima, baixo,
    esquerda, direita) que existam dentro dos limites do grid.
  - Usa if's para verificar cada direcao.

4.3 remove_wall_* / add_wall_* (metodos direcionais)
  - remove_wall_east(current, neighbor): current.wall_east = False,
    neighbor.wall_west = False
  - Analogos para norte, sul, oeste.
  - remove_wall_between: detecta a posicao relativa e chama o metodo
    direcional correto.

4.4 get_unvisited_neighbors(cell) -> list[Cell]
  - Filtra get_neighbors() para devolver apenas vizinhos com
    visited = False. Usado durante a geracao.

4.5 get_accessible_neighbors(cell) -> list[Cell]
  - Filtra get_neighbors() para devolver apenas vizinhos cuja
    parede entre eles esteja aberta. Usado no BFS.

4.6 generate(start_x, start_y) -> None  *** DFS RECURSIVE BACKTRACKER ***
  - Algoritmo:
    1. Marca a celula inicial como visited = True
    2. Coloca-a numa stack (pilha)
    3. Enquanto a stack nao estiver vazia:
       a. Olha para o topo da stack (current = stack[-1])
       b. Se current tem vizinhos nao visitados:
          - Escolhe um aleatoriamente
          - Remove a parede entre current e o vizinho
          - Marca o vizinho como visited
          - Adiciona vizinho a stack
       c. Se nao tem vizinhos nao visitados:
          - Faz pop da stack (backtrack)
  - Resultado: spanning tree (arvore geradora) - maze perfeito
  - Garante: todas as celulas visitadas, sem ciclos, sem blocos 2x2

4.7 is_block_open(x, y) -> bool
  - Verifica se um bloco 2x2 com canto superior esquerdo (x,y)
    esta' totalmente aberto (sem paredes internas).
  - Regra: labirintos nao podem ter blocos 2x2 completamente abertos.

4.8 has_any_open_block() -> bool
  - Percorre todo o grid a procura de algum bloco 2x2 aberto.
  - Devolve True se encontrar algum.

4.9 add_loops(attempts) -> None
  - Para labirintos imperfeitos (PERFECT=False).
  - Faz "attempts" tentativas:
    1. Escolhe celula aleatoria
    2. Se for do padrao 42, salta
    3. Escolhe vizinho aleatorio
    4. Se for do padrao 42, salta
    5. Se ja' tem parede aberta entre eles, salta
    6. Remove a parede
    7. Se criar bloco 2x2 aberto, volta a colocar a parede
  - Garante que nunca cria blocos 2x2 proibidos.

4.10 is_connected(start, end) -> bool
  - BFS simples que verifica se ha' caminho entre duas celulas.
  - Usa fila (lista) e conjunto de visitados.

4.11 bfs(start, end) -> list[Cell]  *** BFS PATHFINDING ***
  - Breadth-First Search para encontrar o caminho MAIS CURTO.
  - Usa dicionario came_from para reconstruir o caminho:
    1. Fila comeca com start
    2. Para cada celula, explora vizinhos acessiveis
    3. Guarda de onde veio cada celula em came_from
    4. Quando encontra end, para
    5. Reconstroi caminho de end ate' start usando came_from
    6. Inverte (reverse) para ficar de start a end
  - Garante: caminho mais curto em numero de celulas.

4.12 path_to_directions(caminho) -> str
  - Converte lista de celulas (caminho) para string de direcoes:
    N (norte), S (sul), E (este), W (oeste)
  - Exemplo: "SSEENNWW..."

4.13 hexa(cell) -> str
  - Codifica as 4 paredes da celula num digito hexadecimal.
  - Bit layout:
    bit 0 = north (valor 1)
    bit 1 = east  (valor 2)
    bit 2 = south (valor 4)
    bit 3 = west  (valor 8)
  - Exemplo: se wall_north=True e wall_south=True, valor = 1+4 = 5 = "5"

4.14 write_output(path, entry, exit) -> None
  - Escreve ficheiro de saida com formato:
    Linha 1: hex encoding da linha 0
    Linha 2: hex encoding da linha 1
    ...
    (linha em branco)
    x_entry,y_entry
    x_exit,y_exit
    direcoes N/S/E/W

4.15 print_maze(entry, exit, caminho, cor, cor_42) -> None
  - Desenha labirinto no terminal com ANSI colors:
    +--+--+  (paredes a "--", cantos a "+")
    |EN|  |  (celulas, EN=entrada verde, EX=saida vermelha)
    |* |  |  (* = caminho em amarelo)
  - Celulas do padrao 42 sao desenhadas com cor_42 (magenta=35)

4.16 apply_42_pattern(entry, exit) -> None
  - Aplica o padrao "42" no centro do labirinto.
  - Passos:
    1. Verifica se o maze e' grande o suficiente (>=10x5)
    2. Calcula offset para centrar: (width-10)//2, (height-5)//2
    3. Cria lista de coordenadas do padrao "42" (forma digital)
    4. Se entry ou exit estiverem dentro do padrao, nao aplica
    5. Para cada celula do padrao:
       a. Marca visited = True (para o DFS nao entrar)
       b. Fecha todas as paredes (N, S, E, W = True)
       c. Fecha tambem as paredes correspondentes nos vizinhos
  - Resultado: o padrao fica isolado, o DFS contorna-o.
  - O padrao nunca bloqueia o caminho entry->exit.

Base pattern do "42":
  O numero 4 ocupa colunas 0-4, linhas 0-4
  O numero 2 ocupa colunas 6-9, linhas 0-4

  4:  ***  (col 0-4, linhas 0,4)
      *  *  (col 0,4, linha 1)
      ****  (col 0-4, linha 2)
          *  (col 4, linha 3)
          *  (col 4, linha 4)

  2:  ****  (col 6-9, linha 0)
          *  (col 9, linha 1)
      ****  (col 6-9, linha 2)
      *     (col 6, linha 3)
      ****  (col 6-9, linha 4)

 7. OUTPUT VALIDATOR (output_validator.py)
===========================================================

Script que valida a consistencia do ficheiro de saida:
  - Le o grid hexadecimal
  - Verifica que paredes vizinhas sao consistentes:
    Parede norte da celula (x,y) = parede sul da celula (x,y-1)
    Parede este  da celula (x,y) = parede oeste da celula (x+1,y)
    etc.
  - Usa operacoes de bits para comparar:
    v & 1          = bit north
    (v >> 1) & 1   = bit east
    (v >> 2) & 1   = bit south
    (v >> 3) & 1   = bit west

===========================================================
 8. ALGORITMOS - DETALHADO
===========================================================

8.1 DFS (Depth-First Search) - Geracao do labirinto
  - Tambem chamado "recursive backtracker"
  - Versao iterativa (com stack explicita) para evitar
    recursao profunda em labirintos grandes
  - Complexidade: O(V+E) onde V = numero de celulas
  - Garante: (1) todas celulas visitadas, (2) sem ciclos,
    (3) sem blocos 2x2 abertos, (4) exactamente 1 caminho
    entre qualquer par de celulas (arvore geradora)

8.2 BFS (Breadth-First Search) - Solucao do labirinto
  - Encontra o caminho MAIS CURTO entre entrada e saida
  - Fila (FIFO): explora celulas por ordem de distancia
  - Usa dicionario "came_from" para reconstruir caminho
  - Complexidade: O(V+E)
  - Garante: caminho minimo em numero de celulas

8.3 Mascara de bits (hexa)
  - Cada celula codificada num digito hex (0-F)
  - Bit 0 (valor 1):  parede norte
  - Bit 1 (valor 2):  parede este
  - Bit 2 (valor 4):  parede sul
  - Bit 3 (valor 8):  parede oeste
  - Exemplo: 0xA = 1010 = north=0, east=1, south=0, west=1

8.4 Bloco 2x2 aberto
  - Proibido: 4 celulas em quadrado sem paredes entre elas
  - Detectado por: is_block_open(x, y) verifica se as paredes
    east de (x,y) e (x,y+1) e south de (x,y) e (x+1,y)
    estao todas abertas
  - add_loops() reverte qualquer remocao que crie bloco 2x2

===========================================================
 11. CONCEITOS IMPORTANTES PARA AVALIACAO
===========================================================

- Spanning tree: arvore que conecta todos os vertices sem ciclos
- DFS vs BFS: DFS explora profundidade, BFS explora largura
- Maze perfeito: exactamente 1 caminho entre qualquer par de celulas
- Maze imperfeito: pode ter multiplos caminhos (loops)
- Stack (DFS): LIFO - Last In, First Out
- Queue (BFS): FIFO - First In, First Out
- Bitmask: codificacao compacta usando bits para representar estado
- ANSI escape codes: \033[31m (vermelho), \033[0m (reset)
- Paredes consistentes: parede norte de A = parede sul de B

===========================================================
 12. POSSIVEIS PERGUNTAS DE AVALIACAO
===========================================================

Q: Porque e' que o DFS garante que nao ha' blocos 2x2?
R: O DFS cria uma spanning tree (arvore). Numa arvore, nao
   ha' ciclos. Um bloco 2x2 aberto seria um ciclo de 4 celulas,
   impossivel numa arvore.

Q: Porque e' que a seed faz o mesmo maze?
R: O random e' inicializado com random.seed(seed), que produz
   sempre a mesma sequencia de numeros aleatorios.

Q: Como e' que o BFS encontra o caminho mais curto?
R: BFS explora celulas por ordem crescente de distancia (fila).
   A primeira vez que encontra a saida, e' pelo caminho mais curto.

Q: Como e' que o padrao 42 nao bloqueia o caminho?
R: As celulas do padrao sao marcadas como visited=True ANTES
   da geracao, e todas as suas paredes sao fechadas. O DFS
   ignora celulas visited=True, entao contorna o padrao.

Q: Porque e' que se usa uma stack no gerador em vez de recursao?
R: Recursao pura podia exceder o limite de recursao do Python
   em labirintos grandes (ex: 100x100 = 10000 chamadas).

Q: O que valida o output_validator?
R: Verifica que paredes vizinhas sao consistentes entre si
   (ex: a parede norte de (x,y) e' a mesma que a parede sul de
   (x,y-1), e ambas devem ter o mesmo valor na codificacao hex).
